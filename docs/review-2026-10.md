# Repository review, October 2026

## Scope and baseline

Reviewed `sehlen/sfqm` at `037d703a365c9ed7379a980ec1473c0788eb0a9d` against the
bundled extended version of *Lattices with many Borcherds products* (dated
August 18, 2014). All proposals are on a review branch; the baseline branch is
unchanged. This review covers the main genus-symbol implementation, anisotropic
search, graph construction, bundled finite-quadratic-module and Weil-invariant
code, build system, and the status of historical helper scripts.

## Compatibility conclusion

The original code requires an update for recent Sage. It uses Python 2 print and
exception syntax, `sys.maxint`, dictionary methods and implicit relative imports.
Those fail before a mathematical computation can start. A syntax-only conversion
is insufficient: exact integer division, Python 3 comparison methods, Cython
compilation, Sage import paths, and the generator returned by modern `uniq` also
need attention. In particular, the generator was not picklable when returning a
parallel graph result.

The branch builds and its initial regression suite passed on Sage 10.7 with
Python 3.12. A final expanded suite and CI provide the current evidence. Sage
10.10 is the latest stable release listed by the upstream GitHub release API at
review time; it was not available in the conda-forge package metadata used for the
local installation. The CI matrix targets both versions; the local 10.7 result
must not be described as a verified 10.10 result.

The replacement setuptools build uses Sage's headers and bundled Cython, removes
unneeded GSL/CBLAS probing and obsolete compiler directives, includes the `psage`
package roots, and avoids `-ffast-math` and host-specific `-march=native`.
Cython language level 2 is retained explicitly until its divisions can be ported
and tested separately. The Python modules use Python 3.

## Confirmed defects and corrections

| Area | Baseline defect | Correction / evidence |
|---|---|---|
| Divisor sum | `sigma(s)` used only the first Jordan component's torsion exponent | Sum all components, as required by (2.7); compare with direct enumeration |
| Search partitioning | Rounded chunk widths can omit the last level; non-default `lower` can overlap intervals | Exact inclusive integer partition, exhaustive small-range checks |
| Candidate filtering | Actual candidates were not checked against `max_order`; a stale `s` was used instead of `ss` for the estimate | Apply both checks to each candidate; compare with unpruned enumeration |
| Graph pruning | `cut_nonsimple_aniso=False` still replaced the primes with an empty list | Retain primes unless that pruning step runs; verify actual expansion |
| Bound hypotheses | Inner graph loop used the prime bound even for primes dividing `6*level(A)` | Restrict this shortcut to the unramified primes in Theorem 4.21; conservative behavior otherwise |
| Worker failures | Workers could be skipped silently, or failure strings could be treated as truthy | Raise on malformed worker results instead of returning incomplete classifications |
| Modular dimension API | Wrong keyword arguments to `V.dimension`, missing scalar dimension import | Repair dispatch and scalar case; verify against Sage scalar dimensions |
| Trivial module | String `1^+1` was rejected by FQM parser; signature tried `.list()` on Python `1`; invariants dimension returned zero | Accept trivial notation, coerce root of unity, return dimension one for trivial invariants |
| Object aliasing | Dictionary construction and Jordan extraction shared nested mutable lists | Copy input data; adjust subtraction to operate on its own entries |
| Reduction and ordering | Removing items while iterating; strict ordering returned true for `a < a` | Aggregate by exponent; deterministic strict ordering |
| General C sets | Composite input used invalid `prime_factors([0])`, undefined `n`, and nonreturned recursion | Implement positive-integer recursion from Definition 5.3; test prime-power composition |
| Odd-prime C code | Dead rank-two branches swallowed an undefined `ep` in a bare exception | Remove branches not present in the paper's rules, restrict expected exceptions to `ValueError` |
| Native invariants | Temporary coordinate buffers leaked in inner loops and ordinary return paths | Free those buffers, including `return_H` path; exception-safety work remains |
| Invariant proofs | Reduction-certificate code uses `table0[l-p]` at `p=0`, wrong coefficients, and inconsistent unpacking for `checks=True` | Public `proof=True` / `checks=True` use exact characteristic-zero computation; lower-level finite-characteristic proof matrix fails explicitly |
| Helpers | Missing imports, uninitialized `precomputed`, incorrect unmatched list for T1, invalid default root bracket | Explicit validation/imports, correct unmatched list, expanding bracket |
| Local uniqueness | Undefined `U` and `V` in even 2-adic branch | Construct the corresponding even rank-two genus symbols explicitly |

The sigma defect can be seen without a large classification run. For
`3^+1.9^-1`, the underlying group is C3 x C9. Its 3- and 9-torsion sizes are 9
and 27, so `sigma(-1) = 2 + sqrt(3)/3`. The old expression uses only the first
Jordan component and gives `1 + 4*sqrt(3)/9`.

For partitioning, `num=10, s=3, lower=1` could stop at level 9. For
`num=10, s=3, lower=2` it could produce overlapping intervals. These are defects
in the search interface, not evidence about the parameters used in 2014.

## Mathematical validation and its limits

The tests deliberately use several reference constructions, rather than just
checking that two copies of the same optimized formula agree:

- Enumerate actual FQM elements and their norms for mixed odd and 2-adic symbols,
  including multiple Jordan blocks; compare both full values and 2-torsion values.
- Compute (2.7) by summing over divisors and counting annihilated elements.
- For every anisotropic symbol of level at most 60, compare the class-number
  expression for beta with the direct sawtooth sum. Compare both dimension routes
  in weights 3, 4 and 5/2, and weight 2 through level 12. The smaller weight-2
  range keeps exact native-invariant computations suitable for routine testing.
- Match the complete sets in Example 5.1 for primes 3 and 7.
- For a small collection of extensions, enumerate isotropic subgroups and check
  the quotient condition defining B(A,p).
- Construct the full S matrix over a cyclotomic field, restrict columns to
  T-invariants, and compute the kernel of S-I. Compare with the optimized
  invariants dimension for small modules, in both characteristics and proof mode.
- Check local/global weight-one-half calculations on small cyclic modules and
  the weight-3/2 correction on `2_1^+1`.
- Compare pruned anisotropic searches to unpruned small searches and serial to
  parallel execution with a nondefault lower bound.
- Check that the graph really expands when preliminary pruning is disabled,
  including serialization through Sage's actual process workers.

The FQM enumeration and genus-symbol formulas share the interpretation of genus
notation, so agreement is not a completely independent proof of every convention.
The S-matrix test is independent of the native invariant-matrix implementation.
The explicit paper example checks the construction rules against the paper itself.

No conclusion that the published 362-lattice classification is incorrect follows
from this review. Conversely, this review does not certify that classification.
A complete reproduction must retain starting bounds, input signatures and ranks,
exact low-weight correction settings, pruning decisions, and final isometry-class
comparison data. The current fixes warrant such a run, tracked separately.

## Code quality priorities

1. Separate the supported library, historical experiments and publication-table
   drivers. `sfqm/Bsets.py` duplicates graph/rule code; the two `test_global.py`
   files contain missing session imports and references to unavailable routines.
   Merely changing their syntax does not make them validated programs.
2. Replace wildcard imports with explicit imports and eliminate broad exception
   handlers. In mathematical search code, swallowing a programming error can look
   like a proof that no candidates exist.
3. Make genus-symbol data immutable and canonical internally. Defensive copying
   fixes the demonstrated aliasing but callers can still mutate private data and
   invalidate cached results or hashes. Remove `eval`-constructed Cartesian
   products and use bounded-state/dynamic algorithms for admissibility checks.
4. Replace raw native allocations by owned buffers or comprehensive `try/finally`
   cleanup. Check integer-overflow bounds for the C-long bilinear forms and array
   sizes. The present patch fixes common-path leaks, not every failure path.
5. Make numerical decision guarantees explicit. Fixed rounding tolerances and
   floating-point pruning are not interval-certified. Add precision escalation
   or interval bounds near zero before claiming certified large computations.
6. Split level/order search arguments, make process counts configurable, and avoid
   nested process/OpenMP oversubscription. Keep exact serial runs as a reference.
7. Add reproducible publication commands and machine-readable golden results;
   distinguish complete classifications from partial runs. Pin runtime versions
   and record provenance for the bundled PSAGE snapshot. Review license metadata
   against the differing headers before declaring a uniform package license.

## Remaining risks

Native allocation failures, overflow on very large inputs, full table
reproduction, and unsupported historical helpers remain open follow-up work.
The lower-level finite-characteristic proof-matrix API now raises rather than
returning its known-broken certificate. The public exact proof path may be slower.
MacOS/Windows builds and the complete old doctest corpus were not validated.
The branch should be reviewed and its current CI results inspected before merge.

## Recorded validation

On October 14, 2026 the expanded suite completed on the local Sage 10.7 /
Python 3.12 environment: **20 tests passed in 14.894 seconds**, after a fresh
editable build. This includes the quotient and low-weight checks listed above.
Sage's fork helper emitted resource/deprecation warnings; it did not fail a test.
The current CI run is the authority for the separately targeted Sage 10.10 image.

## Final CI evidence

[Run 38606014384](https://github.com/sehlen/sfqm/actions/runs/38606014384)
built the installed wheel on both versions. All 20 tests passed on Sage 10.10.
The final local Sage 10.7 run passed all 20 tests in 15.872 seconds. The official
Sage 10.7 container failed with a PARI stack error during finite quadratic
module construction; [issue #5](https://github.com/sehlen/sfqm/issues/5) records
the traceback and investigation needed. The failure remains visible in CI.

CI also exposed the removed global `is_fundamental_discriminant` function in
Sage 10.10; the library now uses the integer method. Tests run outside the source
checkout so that they exercise the installed wheel and its compiled extensions.
Exact invariant kernels use generic field elimination, avoiding one PARI
conversion path without claiming to resolve the broader Sage 10.7 failure.
